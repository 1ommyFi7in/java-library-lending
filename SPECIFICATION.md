# Техническое задание · Библиотека с выдачей книг

[← К README](README.md)

## Рабочий сценарий
Библиотекарь сканирует штрихкод экземпляра и карту читателя. У одной книги бывают несколько экземпляров. После отказа библиотекарь видит причину и может продолжить работу, после перезапуска видит активные выдачи.

## Стартовые данные и команды

Книга `b1` — «Практика Java», экземпляры `c1` и `c2`. Книге `b2` — «SQL на практике» принадлежат `c3` и `c4`, книге `b3` — «Тестирование» экземпляр `c5`. Читатели `r1` и `r2`. Выдач на старте нет. Метки времени берутся из управляемых часов. `loans <readerId>` показывает активные выдачи по ID экземпляра. `save` и `load` адресуют один файл из рабочей папки. В случае успеха команды печатают `OK`, формат уведомления задаётся отдельно. Для примера ввода и вывода используй отправителя, сохраняющего сообщения в памяти.

| Действие | Наблюдаемое состояние |
| --- | --- |
| Выдать c1 читателю r1, c2 читателю r2 | Две независимые выдачи одной книги |
| Попытка выдать c1 читателю r2 | `COPY_ALREADY_LENT`; в журнале новых уведомлений нет |
| Выдать c3 и c4 читателю r1, затем попытаться выдать c5 | Три активных; последняя команда даёт `READER_LIMIT` |
| Возвратить c1 два раза, потом выдать c5 читателю r1 | Успех, `NO_ACTIVE_LOAN`, успех. Старая выдача c1 хранит дату возврата |
| Загрузить локальный файл с усечённой последней записью | `SNAPSHOT_INVALID`; состояние и права на выдачу сохраняются |

Сделай сначала модель и проверку состояний, затем CLI и отправителя, последним добавь снимок. К сдаче приложи схему классов, журнал команд, снимок для повторного запуска и проверку лимита.

## Функциональные требования

- [ ] На старте доступны тестовые экземпляры и читатели. `lend <copyId> <readerId>` открывает выдачу, если экземпляр свободен, читатель существует и имеет меньше трёх активных выдач.
- [ ] `return <copyId>` закрывает активную выдачу. Занятый экземпляр, неизвестный ID, лимит и повторный возврат дают разные ошибки без изменения состояния.
- [ ] При успешной выдаче отправить сообщение через `NotificationSender`. Одна реализация пишет в консоль, другая копит сообщения для проверки.
- [ ] `save` сериализует снимок в `library.bin`. `load` читает только локальный снимок, созданный программой. Повреждённый или несовместимый снимок вызывает ошибку и сохраняет текущее состояние.

## Данные

| Модель | Поля и связи |
| --- | --- |
| Book | `id`, `title` |
| BookCopy | `id`, `bookId`. У книги может быть несколько экземпляров |
| Reader | `id`, `name` |
| Loan | `copyId`, `readerId`, `issuedAt`, `returnedAt`. Без даты возврата выдача активна |

Снимок хранит данные моделей с явным `serialVersionUID`. Отправитель уведомлений остаётся зависимостью сервиса.

## Пример ввода и вывода

```text
> lend c1 r1
OK loan c1 r1
> lend c1 r2
ERROR COPY_ALREADY_LENT
> return c1
OK returned c1
> lend c1 r2
OK loan c1 r2
```

## Нефункциональные требования

- [ ] Поля закрыты, изменения проходят через доменные методы. Связи можно проверить на массивах.
- [ ] Сравнить абстрактный класс с композицией и объяснить выбор на своей модели.

## Приёмка

- [ ] Проверить пример, независимую выдачу второго экземпляра и отказ на четвёртой активной выдаче.
- [ ] После перезапуска и загрузки экземпляр с активной выдачей остаётся занят. При отказе подменённый отправитель не получает сообщений.
